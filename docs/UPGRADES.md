# UPGRADES — план фич для удержания внимания зрителя

> Топ-10 улучшений редактора, отсортирован по соотношению «влияние на удержание / стоимость внедрения».
> Зафиксирован 2026-07-12 по итогам инвентаризации кодовой базы. Статусы «что уже есть» — на момент фиксации.

## Три механики применения

Все фичи ниже работают **локально, на программных алгоритмах** (DSP/эвристики) либо на маленьких on-device ML-моделях (Whisper уже в проекте). Облако и внешние API не нужны. Каждая фича относится к одной из трёх механик:

- **[Эффект]** — рендер-тайм эффект: тумблер/настройка в панели, применяется мгновенно в превью и при экспорте. Без этапа анализа. Неразрушающий (исходник не меняется).
- **[Анализ → предложения]** — кнопка запускает анализ (звук/телеметрия курсора), система расставляет маркеры-предложения на таймлайне, пользователь просматривает, удаляет лишние, жмёт «применить». Прецедент уже есть в коде: auto-zoom (magic wand в `TimelineEditor.tsx`, `zoomSuggestionUtils.ts`) — предложения помечаются `source: "auto"` и при ручном редактировании становятся `manual`.
- **[Обработка]** — разовый локальный прогон ML/DSP по всей дорожке (транскрипция, денойз): прогресс-бар, результат кэшируется, пользователь правит результат.

## Топ-10

### 1. Клик-риппл (подсветка кликов) — [Эффект] — ✅ РЕАЛИЗОВАНО (2026-07-13)
Расходящееся кольцо на клике — визуальный якорь для глаза зрителя, фирменный эффект Screen Studio.
**Что уже есть:** каркас полностью написан — состояние `clickProgress`, `CLICK_RING_FADE_MS`, `clickRingGraphics`, но `drawClickRing()` в `src/components/video-editor/videoPlayback/cursorRenderer.ts` — пустышка (no-op). Клики есть в телеметрии (`interactionType`).
**Осталось:** реализовать отрисовку кольца + тумблер в панели курсора. Самая дешёвая фича списка.
**Итог реализации:** общая математика в `src/lib/cursor/clickRipple.ts` (450 мс, ease-out расширение + затухание, двойное кольцо белое/тёмное для контраста); рисуется во всех трёх путях рендера — Pixi-оверлей (`drawClickRing`), нативное превью (`VideoPlayback.tsx`, Graphics внутри маскированного videoContainer), экспорт MP4/GIF (`frameRenderer.drawNativeCursor`). Слайдер «Волна при клике» (0–100%) в панели курсора, дефолт 50%, ключ `cursor.clickRipple` во всех 13 локалях. Юнит-тесты: `clickRipple.test.ts`.

### 2. Караоке-субтитры (пословная подсветка, TikTok-стиль) — [Обработка] + [Эффект]
Пословная подсветка субтитров — сильнейший фактор удержания для вертикальных шортсов (смотрят без звука).
**Что уже есть:** Whisper-tiny локально (`src/lib/captioning/`), **пословные таймстемпы** уже извлекаются (`transcribeCore.ts`), субтитры превращаются в текстовые аннотации (`annotationsFromCaptions.ts`), система анимаций текста (`src/lib/annotationTextAnimation.ts`), пресет 9:16.
**Осталось:** режим рендера «подсветка текущего слова» (цвет/скейл) + пресеты стилей. UX не меняется: та же кнопка субтитров → транскрипция → правка текста → выбор стиля.

### 3. Автоудаление тишины и пауз — [Анализ → предложения] — ✅ РЕАЛИЗОВАНО (2026-09-17)
Мёртвый воздух — убийца удержания №1 в скринкастах.
**Что уже есть:** аудио-пики уже считаются (`src/hooks/useAudioPeaks.ts`, воркер), механика вырезания — `TrimRegion`, паттерн предложений — auto-zoom.
**Осталось:** детектор тишины (RMS-порог + гистерезис, чистый DSP) → предложить интервалы как trim-регионы → кнопка «применить все». Настройки: порог, мин. длительность паузы, отступы.
**Уточнение (2026-09-17):** сверка по коду нашла, что детектор уже написан — `src/lib/mcp/audioProfile.ts`, для агентского `get_audio_profile`. Осталась не DSP-часть, а порог от материала (фиксированный ломается на тихой и на шумной записи), отступы и подключение. И не «предложения»: трим режет видео независимо от `source`, так что образец — палочка автозума, а не панель приёмки. Подробности: [architecture/silence-removal.md](architecture/silence-removal.md).

### 4. Переходы на стыках вырезок — [Эффект] — ✅ РЕАЛИЗОВАНО (2026-09-16)
Каждый trim-регион создаёт джамп-кат, который режет глаз. Сглаживание склеек = 80% ценности переходов за 20% стоимости.
**Что уже есть:** trim-регионы, motion blur в пайплайне (`motionBlurAmount`), пружинные анимации зума.
**Осталось:** на стыке трима применять crossfade / zoom-punch / whip-pan. Настройка глобальная или per-trim.
**Итог реализации:** общая математика в `src/lib/transitions.ts` (стыки из тримов, альфа по «миллисекундам готового видео от склейки»); растворение держит последний кадр до склейки, затемнение уходит в чёрное и возвращается; блок «Переходы на склейках» в панели эффектов (стиль + длительность 80–800 мс), общий на проект, в файле проекта и в `set_layout` у агента; по умолчанию выключено. Zoom-punch и whip-pan отложены. Подробности и сверка по коду: [architecture/transitions.md](architecture/transitions.md).
**Примечание:** переходы **между клипами** сделаны 2026-09-16 этапом 9 мультиклипа — тем же переключателем, без новых настроек: стык двух записей и стык с карточкой сглаживаются той же математикой. Проект перестал быть одноклиповым; подробности в [architecture/multiclip.md](architecture/multiclip.md). Там же видно, почему эту фичу (#4) стоило делать **до** мультиклипа, а не после: сверка перед этапом 9 опиралась на неё целиком и вдвое сократила его объём.

### 5. Фоновая музыка + автодакинг — [Эффект] (дакинг — авто-DSP без маркеров)
Музыкальная подложка с автоприглушением под голос даёт «продюсерское» ощущение.
**Что уже есть:** аудио-энкодер и муксер (`src/lib/exporter/audioEncoder.ts`, `muxer.ts`), аудио-пики для детекции речи.
**Осталось:** добавление аудиофайла, дорожка музыки на таймлайне, огибающая громкости голоса → гейн-кривая музыки (sidechain-дакинг, чистый DSP), громкость/фейды. Дакинг применяется автоматически в превью/экспорте, без этапа просмотра маркеров.

### 6. Оверлей нажатых клавиш (keystroke display) — [Эффект] (+ захват при записи)
Must-have для туториалов: зритель видит, *как* сделано действие.
**Что уже есть:** телеметрия курсора при записи (`src/lib/cursorTelemetryBuffer.ts`), рендер плашек можно строить по образцу аннотаций.
**Осталось:** захват клавиатуры на этапе **записи** (main-процесс, через IPC — единственная фича топа с работой в `electron/`) + рендер-тайм оверлей со стилями. В редакторе — просто тумблер и стиль, анализ не нужен.

### 7. Включить blur/mosaic-регионы — [готово, за флагом]
Скрытие чувствительных данных — про публикуемость видео.
**Что уже есть:** фича **полностью написана** — `BlurSettingsPanel.tsx`, `src/lib/blurEffects.ts`, фигуры (прямоугольник/овал/от руки), blur и мозаика, ряд на таймлайне — но выключена флагом `BLUR_REGIONS_ENABLED = false` в `src/components/video-editor/featureFlags.ts`.
**Осталось:** выяснить причину отключения (баги? производительность? экспорт?), дожать и включить. Механика полностью ручная: пользователь сам рисует регионы.

### 8. Шумоподавление голоса — [Обработка]
Плохой звук выключает видео быстрее плохой картинки.
**Что уже есть:** прецедент on-device ML (`@xenova/transformers` для Whisper), извлечение аудио (`extractMono16k.ts`).
**Осталось:** RNNoise (wasm, лёгкий) как тумблер: разовый прогон по дорожке с прогрессом, кэш результата, A/B-прослушивание до/после.

### 9. Speed ramping + авто-таймлапс скучных мест — [Эффект] + [Анализ → предложения]
**Что уже есть:** `SpeedRegion` с константной скоростью (`customPlaybackSpeed.ts`), телеметрия курсора, аудио-пики.
**Осталось:** (а) плавный разгон/торможение на границах региона — чистая математика easing'а; (б) эвристика «долго нет кликов и речи → предложить ускорение 4×» — тот же паттерн предложений, что и auto-zoom/тишина.

### 10. Интро/аутро-шаблоны и брендинг — [Эффект/шаблоны]
Титульная карточка, финал с CTA, логотип-вотермарка.
**Что уже есть:** аннотации (текст + изображение + анимации), кастомные шрифты.
**Осталось:** концепция «сцены до/после записи» поверх одноклиповой модели, библиотека шаблонов, вотермарка в углу. Самая нишевая фича — в конце списка.
**Уточнение (2026-09-14):** «поверх одноклиповой модели» — обходной путь, придуманный из-за её отсутствия. В [architecture/multiclip.md](architecture/multiclip.md) карточка сделана обычным клипом без видеоисточника и стоит этапом 2: она прогоняет всю модель секвенции насквозь, минуя второй видеодекодер и склейку звука.

# Камера — план улучшений

> Зафиксирован 2026-07-13 по итогам инвентаризации вебкам-пайплайна.
>
> **Архитектурная база:** камера пишется отдельным файлом-сайдкаром (`recording-<id>-webcam.webm`), композитинг — только в превью (`VideoPlayback.tsx`, DOM-оверлей) и при экспорте (`frameRenderer.ts`, canvas). Общая геометрия — `src/lib/compositeLayout.ts` (`computeCompositeLayout`). Благодаря этому все фичи ниже — неразрушающие рендер-тайм эффекты либо локальная обработка, без изменения этапа записи.
>
> **Что уже есть (не путать с новым):** формы `rectangle | circle | square | rounded` (`webcamMaskShapes.ts`), размер 10–50%, перетаскивание позиции, зеркало, реактивный зум, 4 пресета раскладки (`picture-in-picture | vertical-stack | dual-frame | no-webcam`), тень (`getWebcamLayoutCssBoxShadow`).

## Топ-7 камеры

### К1. Камера-сегменты на таймлайне — [Эффект] — самая мощная фича блока
Позиция/размер/раскладка камеры на интервал: интро — камера на весь экран («talking head»), середина — маленький кружок, важный момент — скрыть совсем. Сейчас все настройки камеры глобальные на весь ролик.
**Что уже есть:** паттерн интервалов на таймлайне полностью отработан (`ZoomRegion`, `SpeedRegion`, `TrimRegion`), пружинные анимации в пайплайне зума, общий `computeCompositeLayout` для превью и экспорта.
**Осталось:** ряд «камера» на таймлайне с сегментами, переопределяющими layout/size/position/видимость; плавная пружинная интерполяция между состояниями на границах сегментов.

### К2. Анимация появления/ухода камеры — [Эффект]
Pop-in с пружиной в начале, slide-out при скрытии. Убирает эффект «статичной наклейки». Обязательная пара к К1 (без неё смена состояний будет дёргаться).
**Что уже есть:** пружинная математика зума.
**Осталось:** applied-анимация к `webcamRect` в обоих путях рендера (DOM-оверлей + canvas-экспорт).

### К3. Рамка / кольцо — [Эффект]
Толщина, цвет, градиентное кольцо вокруг кружка (стиль сторис).
**Что уже есть:** тень уже рисуется в обоих путях (`getWebcamLayoutCssBoxShadow` + canvas-тени в `frameRenderer.ts`), clip-path-маски (`webcamMaskShapes.ts`).
**Осталось:** тривиальное расширение того же кода: настройки border width/color/gradient в `SettingsPanel`, отрисовка в превью (CSS) и экспорте (canvas stroke по тому же clip path).

### К4. «Камера уворачивается от действия» — [Анализ → предложения] — фирменная фишка
Если курсор/зум-регион залезает под камеру — она автоматически переезжает в другой угол или временно фейдится. Нет ни у Screen Studio, ни у Loom.
**Что уже есть:** телеметрия курсора при записи (`src/lib/cursorTelemetryBuffer.ts`), зум-регионы с геометрией, паттерн предложений auto-zoom (`zoomSuggestionUtils.ts`, `source: "auto"`).
**Осталось:** эвристика пересечения «активность курсора/зума × прямоугольник камеры» → предложить сегменты перемещения/скрытия (генерирует сегменты К1) → пользователь просматривает и применяет.

### К5. Реакция на речь — [Эффект] (авто-DSP)
Лёгкое увеличение/свечение камеры, когда автор говорит; автоуменьшение/скрытие при долгой тишине. Чистый DSP, рендер-тайм, без облака.
**Что уже есть:** аудио-пики (`src/hooks/useAudioPeaks.ts`, воркер) — та же огибающая, что нужна автодакингу (п.5 основного топа).
**Осталось:** RMS-огибающая → гейн-кривая скейла/свечения камеры с гистерезисом; тумблер + интенсивность в панели.

### К6. Вырезание фона (floating head) — [Обработка] — вау-фича
On-device сегментация человека: голова без прямоугольника «плавает» над записью. Дифференциатор уровня mmhmm.
**Что уже есть:** прецедент on-device ML (`@xenova/transformers` для Whisper), механика «разовый прогон с прогрессом + кэш» (транскрипция), отдельный вебкам-файл — сегментировать можно независимо от экрана.
**Осталось:** модель сегментации (MediaPipe Selfie Segmentation / аналог в transformers.js), прогон по дорожке с кэшем масок, альфа-композитинг маски в превью и экспорте.

### К7. Авто-кадрирование лица — [Обработка]
Цифровой punch-in внутри кадра камеры, чтобы лицо всегда было по центру (аналог Center Stage).
**Что уже есть:** aspect-crop камеры уже реализован в экспортере (`frameRenderer.ts`), т.е. кроп-математика наполовину готова.
**Осталось:** face detection on-device (лёгкая модель), сглаженная траектория кропа (low-pass, чтобы не дёргалось), применение той же траектории в превью и экспорте.
