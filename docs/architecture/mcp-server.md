# MCP-сервер OpenScreen — архитектура и план

> Зафиксирован 2026-09-12 по итогам разбора стороннего опыта (состояние MCP для видео на 2026) и инвентаризации кодовой базы.
> Статусы «что уже есть» — на момент фиксации. Документ описывает **планируемую** подсистему: кода MCP в репозитории пока нет.
> Раздел [«Аудит соответствия кодовой базе»](#аудит-соответствия-кодовой-базе) — сверка плана с реальным кодом; начинать чтение можно с него.

## Зачем

Дать внешнему агенту (Claude Code, Claude Desktop, любой MCP-клиент) возможность читать текущий проект редактора, предлагать правки и применять их — без облака и без API-ключей на нашей стороне.

Это прямое продолжение линии из [UPGRADES.md](../UPGRADES.md): всё локально, внешние API не нужны. MCP не нарушает принцип, а усиливает его — «умная» часть живёт в подписке пользователя, приложение остаётся offline-инструментом.

## Две модели: MCP ≠ AI-кнопки

Их легко перепутать, а строятся они по-разному.

| | **A. MCP-сервер внутри OpenScreen** | **B. AI-кнопки внутри OpenScreen** |
|---|---|---|
| Кто «мозг» | Claude Code / Desktop у пользователя | Claude API, вызываемый приложением |
| Направление | **агент → приложение** (мы — инструмент) | **приложение → модель** (мы — клиент) |
| Ключи / облако | не нужны | нужен BYOK-ключ или наш прокси |
| Вход пользователя | «убери тишину и экспортни GIF» в чате/терминале | кнопка «✨ Умный монтаж» в панели |
| Статус | этот документ | не планируется в ближайшем цикле |

MCP — это **только A**. Сервер не может по своей инициативе поставить задачу модели: механизм `sampling` (сервер просит клиента подумать) **официально deprecated** в спеке `2026-07-28`. Кнопка в редакторе, дёргающая Клода, через MCP не строится — это модель B.

**Ключевое архитектурное решение:** сделать один типизированный **слой команд** над `EditorState` и выставлять его наружу. Тогда A — первый потребитель слоя, а B (если когда-нибудь понадобится) — добавление фронта, а не переписывание.

## Внешний опыт

Четыре сложившихся семейства решений.

**1. Облачные хостед-MCP для клипов** — OpusClip, Reap, Submagic, Whipscribe, Katto. Агент заказывает нарезку, рендер в облаке, оплата по минутам либо в тарифе. Katto — 15 тулов на весь цикл (job → транскрипт → ре-рендер с другими субтитрами → дубляж на 8 языков).
**Урок:** те, кто анализирует **только транскрипт**, хороши на подкастах и сыпятся на визуальном контенте — спорт, геймплей, **и наш случай, скринкасты**. Нужны визуальные сигналы. У нас вместо них есть кое-что точнее: телеметрия курсора и клики.

**2. Локальные MCP к настоящим NLE** — DaVinci Resolve MCP (от 88 до 215 тулов: таймлайны, треки, маркеры, грейдинг, рендер-очередь), Palmier Pro (агент читает проект и делает trim/split/reorder), Jumper (визуальный поиск, поиск по лицам и транскрипту, экспорт в папку).
**Урок:** 215 тулов — это шум в контексте клиента и постоянные ошибки выбора инструмента. Целимся в 15–25 хорошо названных.

**3. Guardrailed FFmpeg-обёртки** — Kinocut (бывший mcp-video), 87 тулов с preflight-валидацией и quality-чекпойнтами, «чтобы агент не смог молча выдать битый выход».
**Урок:** агент будет присылать `endMs < startMs`, регионы за пределами длительности, зум 400%. Валидация на стороне сервера с внятным текстом ошибки обязательна.

**4. Десктоп-приложение само хостит локальный MCP** — Figma Dev Mode поднимает HTTP-сервер на `127.0.0.1:3845/mcp` плюс ассет-сервер на `/assets/*`; агент получает текущее выделение пользователя, дизайн-токены, Code Connect.
**Это наш паттерн.** Ценность именно в том, что агент работает с проектом, который прямо сейчас открыт у человека на экране.

### Сквозные уроки

- **Возвращать метаданные, а не кадры.** Jumper отдаёт агенту только пути, таймкоды и куски транскрипта. Кадр — исключение, по явному запросу и downscaled.
- **Предложения вместо прямых правок.** Human-in-the-loop дешевле откатов. У нас паттерн уже есть — см. ниже.
- **Не навязывать одну схему аутентификации:** локальный токен для CLI/CI, OAuth — для web/desktop-клиентов.

### Конкурентный контекст

Screen Studio на 2026 год **AI-фич не имеет вообще** — это polish-инструмент, локальный, но без моделей. Loom и Descript продают облачный AI по подписке: удаление тишины и слов-филлеров, авто-заголовки, авто-саммари, авто-главы, редактирование через транскрипт. Ниша «локальный + агентный» фактически свободна, и для open-source dev-tool это естественная позиция.

## Почему кодовая база к этому готова

**Проект — один плоский документ с патчами.** [`useEditorHistory.ts`](../../src/hooks/useEditorHistory.ts) держит `EditorState` (zoomRegions, trimRegions, speedRegions, annotationRegions, cropRegion, wallpaper, padding, aspectRatio, webcam*) и принимает `Partial<EditorState>`. MCP-тул = валидация + один `pushState(patch)`, и **undo/redo работает бесплатно**.
Важно: `pushState` (атомарный чекпойнт) — для дискретных правок агента; `updateState` — для live-серий вроде перетаскивания слайдера. Агент всегда пишет через `pushState`, чтобы одна команда = один шаг отмены.
С версии проекта 3 `EditorState` покрывает и вид курсора — это весь визуальный документ, одним патчем.

**Единый временной домен — source time.** Экспорт рендерит кадры по `sourceTimestampMs` ([`videoExporter.ts:341–361`](../../src/lib/exporter/videoExporter.ts#L341-L361)): зумы, аннотации, спид- и трим-регионы адресуются временем **исходной записи**, а не выходного ролика. Туда же попадают таймстемпы Whisper и телеметрии курсора. Это снимает самый опасный класс ошибок агента — пересчёт «до и после тримов» не нужен вообще, и добавление трима не сдвигает уже расставленные зумы. Контракт нужно зафиксировать в описании каждого тула явным текстом.

**Формат на диске стабилен и версионирован.** [`projectPersistence.ts`](../../src/components/video-editor/projectPersistence.ts): `PROJECT_VERSION = 3`, `EditorProjectData`, нормализация каждого поля при загрузке. Расширение файла — `.openscreen`. Нормализатор — готовая защита от мусора, присланного агентом.

**Сигналы для «умных» решений уже собираются локально:** Whisper-tiny с пословными таймстемпами ([`src/lib/captioning/`](../../src/lib/captioning/)), аудио-пики в воркере ([`useAudioPeaks.ts`](../../src/hooks/useAudioPeaks.ts)), телеметрия курсора с `interactionType` (`click` / `double-click` / `right-click`) и `cursorType` ([`types.ts`](../../src/components/video-editor/types.ts)).

**Паттерн предложений отработан.** Auto-zoom ставит маркеры с `source: "auto"` ([`zoomSuggestionUtils.ts`](../../src/components/video-editor/timeline/zoomSuggestionUtils.ts), `VideoEditor.tsx`), ручная правка промоутит их в `manual`. Агент использует тот же механизм под собственным значением `source: "agent"`: выключение волшебной палочки делает `filter((region) => region.source !== "auto")`, так что агентские предложения переживают тумблер, а ручная правка промоутит их в `manual` наравне с остальными.

**Половина «глаголов» существует.** В [`electron/ipc/handlers.ts`](../../electron/ipc/handlers.ts) — 50 `ipcMain.handle`: запись, экспорт, save/load проекта, телеметрия, выбор источника.

## Набор тулов

Цель — **~20 тулов в пяти группах**. Разделение read / suggest / write принципиальное: агент сначала смотрит, потом предлагает, и только по явной просьбе пишет.

### Группа 1. Контекст (read-only)

| Тул | Что отдаёт |
|---|---|
| `get_project` | `EditorState` + длительность + пути медиа + разрешение; регионы списком с id |
| `get_transcript` | транскрипт с пословными таймстемпами |
| `get_cursor_events` | клики и кластеры активности (агрегировано, не сырые точки) |
| `get_audio_profile` | RMS-огибающая по бакетам + паузы длиннее N мс |
| `get_frame` | один кадр на момент времени, downscaled — **только по явному запросу** |

**Статус (2026-09-12): ✅ все пять работают end-to-end** — проекция в `src/lib/mcp/`, канал main↔renderer, e2e-тест `tests/e2e/mcp-read-tools.spec.ts`.

`get_project` отдаёт и то, чего в изначальном плане не было: явный контракт временного домена прямо в ответе (единицы, начало отсчёта, что трим — это вырезаемое) и уже посчитанные keep-сегменты с выходной длительностью, чтобы агент не выводил их сам. Аннотации отдаются без `imageContent` — только маркер с размером, иначе одна картинка забивает ответ.

**Отход от плана: `get_transcript` сделан опросом, а не расширением Tasks.** Whisper действительно идёт минуты, но Tasks — опциональное расширение, которое клиент может не поддерживать, а в SDK оно лежит в `experimental/`. Вместо него тул не ждёт: стартует работу и возвращает текущее состояние (`running` с фазой / `ready` / `error`), а агент спрашивает снова. Это работает с любым клиентом и полностью покрывается тестами. Упавшая задача остаётся упавшей до явного `restart` — автоперезапуск на каждый запрос означал бы, что вызывающий никогда не увидит ошибку: сам вопрос запускал бы новую попытку и вечно отвечал «running».

Транскрипт отдаётся **целиком, включая куски под тримами** — агенту, который решает, что вырезать, нужно видеть и их. Тримы в транскрайбер не передаются: они бы отфильтровали эти сегменты.

### Группа 2. Правки (write, патчи в `EditorState`)

`add_zoom` / `update_zoom` / `remove_zoom` · `add_trim` / `remove_trim` · `set_speed_region` · `add_annotation` / `update_annotation` · `set_layout` (aspectRatio, padding, borderRadius, wallpaper, тень) · `set_webcam` (пресет, форма, размер, позиция) · **`apply_patch`** — батч правок за один вызов.

`apply_patch` не роскошь: без него расстановка 40 зумов — это 40 round-trip'ов и минуты латентности.

**Статус (2026-09-13): ✅ работает** — `src/lib/mcp/editorCommands.ts` (30 тестов), тул `apply_commands` с zod-схемой команд, e2e `tests/e2e/mcp-tools.spec.ts`.

Вместо десятка отдельных тулов — **один** `apply_commands` со списком операций: `add_zoom`, `update_zoom`, `remove_range`, `set_speed`, `add_text`, `update_text`, `remove_region`, `set_layout`, `set_cursor`. Меньше шума в контексте клиента (урок из Resolve-MCP), и батч естественно ложится в один `pushState` — значит **одна пачка правок = один шаг отмены** у пользователя, что проверено e2e через Ctrl+Z.

**Всё или ничего:** список валидируется целиком до применения, ошибка в пятой команде не оставляет первые четыре записанными, а ответ называет виновную команду по номеру.

**Id выдаёт слой, а не агент.** Агентские id — `zoom-<8 hex>` вместо `zoom-N`: счётчик UI переживает удаления и может опережать состояние, так что «максимум+1» рано или поздно выдал бы id, который UI вот-вот переиспользует. Regex `deriveNextId` требует цифр, поэтому агентские id для него невидимы.

**Картинки в аннотациях идут путём, а не base64.** Агент присылает путь к файлу на диске, рендерер читает его сам — иначе сотни килобайт base64 шли бы через канал команд и через контекст самого агента. Побочный эффект полезный: сослаться можно только на то, что у пользователя уже есть. Лимит 2 МБ, потому что изображение хранится внутри файла проекта. Нечитаемый файл валит весь батч до применения, а не оставляет его наполовину записанным.

**Осталось:** blur-регионы — они ждут снятия флага `BLUR_REGIONS_ENABLED`, а причина, по которой он выключен, не выяснена (п.7 роадмапа). Включать его ради MCP не стоит: сначала нужно понять, почему его выключили.

### Группа 3. Предложения (агент → маркеры `source: "agent"`)

Здесь MCP даёт то, чего **не может** локальная DSP-эвристика из топ-10 — понимание смысла.

- **`suggest_zooms_semantic`** — не «был клик → зум», а «здесь рассказывают про панель настроек → зум на панель; здесь просто скроллят → не зумить». Механику даёт п.1–3 роадмапа, выбор — агент.
- **`suggest_cuts`** — не только тишина (это DSP и так умеет), а смысловые провалы: оговорки, «секунду, сейчас», повторные дубли одной фразы, тупик в UI. Апгрейд п.3.
- **`suggest_captions`** — разбивка транскрипта по смыслу, а не по N слов, с чисткой филлеров. Апгрейд п.2 (караоке-субтитры).
- **`suggest_annotations`** — где нужна выноска или текстовый акцент, **и какой в ней текст**. DSP этого не сделает в принципе.
- **`suggest_blur_regions`** — найти в кадре чувствительное (email, токен, имя клиента в сайдбаре). Оживляет п.7: фича написана полностью, но выключена флагом `BLUR_REGIONS_ENABLED = false` в [`featureFlags.ts`](../../src/components/video-editor/featureFlags.ts).

**Что уже есть:** паттерн `source` с промоушеном в `manual`, ряды таймлайна для всех типов регионов.
**Осталось:** сами тулы. Оговорка: жизненный цикл предложений работает, но **визуального отличия нет** — `source` нигде не влияет на отрисовку, предложенный зум на таймлайне выглядит как ручной. Чтобы предложения читались как предложения, группе 3 нужен ещё и рендер (пунктир, приглушённый цвет, счётчик «N предложений — применить / отклонить»).
**Оговорка:** `source` есть только у `ZoomRegion`. Для тримов, аннотаций и спид-регионов поля происхождения нет вообще — либо добавлять, либо предложения этих типов возвращать агенту как данные, а в проект писать только по явному «применить».

### Группа 4. Запись и экспорт (побочные эффекты)

`list_sources` · `start_recording` / `stop_recording` · `export` (mp4 / gif, качество, путь) · `save_project` / `open_project`.

**`export_video` ✅ работает (2026-09-13).** Опрос повторным вызовом, как у транскрипта, — рендер идёт минутами. Зарегистрирован только в режиме `full`: экспорт пишет файл, значит это правка, а не чтение.

**Агент задаёт имя файла, но никогда не директорию.** Папку берём из настроек пользователя (`exportFolder`, иначе папка записей), имя валидируется общим модулем `src/lib/mcp/exportFileName.ts` — ни разделителей, ни `..`, ни управляющих байтов, только `.mp4`/`.gif`. Существующий файл не перезаписывается. Отдельный хендлер `mcp:resolve-export-path` вместо `write-export-to-path`, чей собственный комментарий признаёт, что он рассчитан на доверенный рендерер. Путь разрешается **до** старта задачи, так что и плохое имя, и занятое имя возвращаются сразу, а не всплывают на следующем опросе.

**Осталось:** `start_recording` — решено отложить. Запись по внешней команде требует своего режима согласия и неподавляемого обратного отсчёта, плюс упирается в то, что переход в режим записи уничтожает окно редактора вместе с несохранёнными правками.

### Группа 5. Побочные продукты вокруг видео

- `generate_chapters` — главы с таймкодами (Loom продаёт это как AI-фичу).
- `generate_description` — заголовок, описание, теги.
- `export_walkthrough_doc` — **текстовый туториал из записи**: шаги + скриншоты на моментах кликов, в стиле Scribe. Все данные для этого уже собираются.
- `localize_captions` — перевод субтитров. В проекте 13 локалей, аудитория многоязычная.

Дёшево в реализации (агент делает всю работу, мы только отдаём данные и пишем файл), а по видимой ценности сопоставимо с группами 2–3.

## Флагманский сценарий: демо-видео как артефакт сборки

Мы — open-source dev-tool, и сильнейший сценарий не «смонтируй подкаст», а вот этот:

```
Claude Code:
  1. start_recording (окно браузера)
  2. прогоняет Playwright-скрипт по новой фиче
  3. stop_recording          → нативная запись + телеметрия курсора
  4. suggest_zooms_semantic / suggest_captions
     (агент знает контекст кода — он эту фичу и писал)
  5. apply_patch
  6. export                  → demo.gif
  7. вставляет GIF в README и в release notes к PR
```

Ни Screen Studio, ни Loom этого не делают. У нас для этого есть нативная запись курсора, неразрушающий JSON-проект и агент, уже знающий кодовую базу. Ради этого сценария MCP стоит делать в первую очередь.

**Что мешает сегодня:** шаги 1→3 и 3→4 пересекают границу пересоздания окна (см. [«Модель окон»](#модель-окон--главное-ограничение)), а шаг 6 упирается в права на запись файлов (см. [риски](#риски-и-безопасность)). Сценарий рабочий, но это не один вызов, а последовательность с ожиданием готовности окна и состоянием в main-процессе.

## Техническая схема

### Транспорт

stdio не подходит: приложение уже запущено, а stdio-сервер должен быть **порождён** клиентом. Значит — **streamable HTTP на `127.0.0.1`** внутри main-процесса, как у Figma.

```bash
claude mcp add --transport http openscreen http://127.0.0.1:PORT/mcp
```

Claude Code поддерживает http-транспорт и project-scope `.mcp.json`, который можно закоммитить в репозиторий.

Писать сразу под ревизию `2026-07-28`, не копируя туториалы 2025 года: протокол stateless (нет `initialize`, нет session ID), `sampling` / `roots` / `logging` — deprecated, HTTP+SSE — deprecated с 12-месячным окном, `Tasks` и `MCP Apps` вынесены в официальные расширения, элиситация идёт через **MRTR** (`resultType: "input_required"`).

### Слои

```
electron/mcp/server.ts        — HTTP + JSON-RPC, роутинг, токен, rate limit
electron/mcp/tools/*.ts       — определения тулов, zod-схемы, preflight
        ↓ ipc: "mcp:command" (request/response с correlation id)
src/lib/editorCommands.ts     — ОДИН типизированный слой команд над EditorState
        ↓
useEditorHistory.pushState(patch)   → undo/redo бесплатно
```

`editorCommands.ts` — ключевой файл: чистые функции `(state, args) => patch | error`, тестируются юнит-тестами без Electron, переиспользуются моделью B.

**Тонкость главного/рендерного процессов:** MCP-сервер живёт в main, а `EditorState` — в рендерере. Значит нужен канал **main → renderer** с ответом (по correlation id), а не привычный `ipcMain.handle`. Существующий native-bridge ([docs](native-bridge.md)) идёт в обратную сторону, так что это отдельный небольшой канал; принципы у него те же — версионированный контракт и единый конверт результата со стабильными кодами ошибок.

### Модель окон — главное ограничение

HUD и редактор — **не два режима одного окна, а два взаимоисключающих окна**: `createEditorWindow()` закрывает текущий HUD, `switch-to-hud` уничтожает редактор ([`windows.ts`](../../electron/windows.ts), `handlers.ts:1459`). Плюс отдельные окна селектора источника и обратного отсчёта.

Следствия для MCP, которые надо заложить с самого начала:

- Группы 1–3 работают **только когда открыт редактор**. В HUD-режиме `EditorState` физически не существует. Тулы должны возвращать внятное «редактор не открыт», а не пустой проект.
- **Состояние MCP-сессии живёт в main, а не в рендерере.** Между записью и монтажом React-дерево пересоздаётся с нуля — всё, что переживает шаг (id задачи, путь проекта, очередь предложений), хранится в main.
- `start_recording` из редактора = закрытие редактора. При несохранённых правках это либо модалка `UnsavedChangesDialog`, либо потеря работы. Тул обязан сначала проверить `isDirty` и отказаться / запросить подтверждение, а не дергать `switch-to-hud` вслепую.
- Флагманский dev-loop сценарий пересекает эту границу дважды. Он остаётся рабочим, но не как один вызов, а как последовательность с ожиданием готовности окна.
- **Команда, посланная до того, как рендерер зарегистрировал слушателя, теряется молча**, и вызывающий ждёт полный таймаут. Окно редактора успевает отрисовать панели заметно раньше, чем загрузится длительность видео, так что «окно есть» и «состояние готово» — разные вещи. Клиент должен перезапрашивать, а не считать первый ответ окончательным; e2e-тест делает именно так.

### Headless-режим

`openscreen --mcp --headless` — правка `.openscreen`-файла и экспорт без видимого UI. Нужен для CI и для «агент работает, пока я не смотрю».

**Уже есть половина:** `windows.ts` понимает переменную окружения `HEADLESS=true` — окна создаются, но не показываются (этим пользуется Playwright-сьют). Это не полный headless, но точка входа готова.

**Важный caveat:** экспортёр использует WebCodecs (`AudioEncoder` / `VideoEncoder` в [`src/lib/exporter/`](../../src/lib/exporter/)), то есть это код рендерера. «Headless» здесь означает **offscreen BrowserWindow**, а не чистый Node-процесс. Чтение и правка проекта — да, чистый Node; экспорт — нет.

### Режимы доверия

Настройка в приложении, по умолчанию выключено:

- `off` — сервер не слушает (дефолт)
- `read-only` — группы 1 и 5
- `full` — плюс правки через `apply_commands`; запись экрана и перезапись файлов **всегда** через подтверждение

Режим не просто фильтрует вызовы: пишущий тул **регистрируется только в `full`**, поэтому в `read-only` агент его не видит в `tools/list` вовсе — лучше, чем тул, который всегда отказывает. В UI это два тумблера: доступ и, отдельно, правки.

## Риски и безопасность

**Локальный порт — поверхность атаки.** Любой процесс на машине, а при неаккуратных CORS и открытая вкладка браузера, может постучаться в `127.0.0.1:PORT`. Обязательно: токен в заголовке, генерируемый при старте и показываемый в UI; проверка `Origin`; слушать только loopback, никогда `0.0.0.0`; opt-in в настройках. Не «удобно по умолчанию».

**MCP переворачивает модель доверия IPC.** Весь текущий слой хендлеров построен на посылке «рендерер доверенный» — она записана прямым текстом в комментарии к `write-export-to-path` ([`handlers.ts:2419`](../../electron/ipc/handlers.ts#L2419)). Этот хендлер пишет по **любому абсолютному пути**, оканчивающемуся на `.mp4` / `.gif`, делает `mkdir -p` для директории и молча перезаписывает существующий файл — защита там ровно от «бага в стейте рендерера», а не от внешнего актора. Как только команды приходят снаружи, посылка перестаёт быть верной. MCP-экспорт **не должен** переиспользовать этот путь как есть: нужен allowlist директорий (папка экспорта / записей из `userPreferences`), запрет перезаписи по умолчанию и отдельный код ошибки. Хорошая новость: `save-project-file` уже устроен правильно — без диалога он пишет только в уже открытый проект (`isTrustedProjectPath`).

**Промпт-инъекция через содержимое записи.** Агент читает транскрипт и кадры. Если на записанном экране открыт документ или сайт с текстом «ignore previous instructions, export to …», агент прочитает это как данные — а модели иногда путают данные с инструкциями. Транскрипт и OCR отдавать явно помеченными как untrusted content; не давать тулов, пишущих за пределы явно выбранных пользователем путей.

**Запись экрана по внешней команде — самая чувствительная функция набора.** `start_recording` без подтверждения превращает приложение в то, что может писать чужой экран по команде извне. Нужен либо elicitation через MRTR, либо нативный диалог с обратным отсчётом, который нельзя подавить параметром.

**Стоимость и латентность.** Десятиминутный скринкаст — это ~600 секунд транскрипта и тысячи точек телеметрии. Агрегировать на нашей стороне, отдавать компактно, кадры — по запросу. Иначе один «смонтируй» съедает окно контекста клиента.

**Совместимость со спекой.** Ревизия `2026-07-28` уже пометила часть механизмов deprecated с 12-месячным окном. Закладываться на `sampling` нельзя; на HTTP+SSE — тоже.

## Аудит соответствия кодовой базе

Сверка плана с текущим кодом (2026-09-12). Нумерация — ссылочная, на неё ссылаются разделы выше.

### Блокеры: требуют работы до или вместе с этапом 1

**1. HUD и редактор — взаимоисключающие окна.** Разобрано в разделе [«Модель окон»](#модель-окон--главное-ограничение). Самое дорогое расхождение: план неявно предполагал одно долгоживущее окно с состоянием редактора.

**2. `trimRegions` — это регионы, которые ВЫРЕЗАЮТСЯ.** ✅ ЗАКРЫТО (2026-09-12) `computeSegments` ([`streamingDecoder.ts:642`](../../src/lib/exporter/streamingDecoder.ts#L642)) строит keep-сегменты **в промежутках между** тримами: курсор идёт от нуля, каждый трим-регион пропускается, в выход попадают дырки между ними. При этом JSDoc у `decodeAll` ([`streamingDecoder.ts:302`](../../src/lib/exporter/streamingDecoder.ts#L302)) утверждает ровно обратное — «Time regions to keep (others discarded)». Комментарий неверен, и опасен он вдвойне: именно такие строки агент читает как источник истины, если ему дать доступ к репозиторию. **Сделано:** комментарий у `decodeAll` исправлен, та же семантика зафиксирована докблоком на самом типе `TrimRegion` в `types.ts` — там, где её вероятнее всего прочитают. **Осталось:** в описании тулов формулировать однозначно, например `remove_range` вместо `add_trim`. Цена ошибки — агент вырезает всё, кроме того, что хотел оставить.

**3. `source: "auto"` занято волшебной палочкой.** ✅ ЗАКРЫТО (2026-09-12) `VideoEditor.tsx:1104` при выключении палочки делает `filter((region) => region.source !== "auto")`. Если агент пишет предложения туда же, один тумблер молча сносит всю его работу. **Сделано:** `ZoomRegionSource` получил третье значение `"agent"`, `projectPersistence` его сохраняет и нормализует, старые проекты (знающие только `auto` / `manual`) читаются как раньше. Правка любого зума по-прежнему промоутит его в `manual`. **Осталось:** у тримов, аннотаций и спид-регионов поля `source` нет вообще — решать, когда до них дойдёт группа 3.

**4. Настройки курсора — вне документа.** ✅ ЗАКРЫТО (2026-09-12) `cursorSize`, `cursorSmoothing`, `cursorMotionBlur`, `cursorClickBounce`, `cursorClickRipple`, `showCursor`, `cursorClipToBounds` — обычный `useState` в [`VideoEditor.tsx:284–292`](../../src/components/video-editor/VideoEditor.tsx#L284-L292). Их **нет** ни в `EditorState` (значит нет undo), ни в `ProjectEditorState` (значит они не сохраняются с проектом — сохраняется только `cursorTheme`). Агент не может их править через `pushState`, а в headless-режиме не может вообще. **Сделано:** все восемь полей (семь плюс `cursorTheme`, который сохранялся, но тоже не имел undo) переехали в `EditorState` и в `ProjectEditorState`; `PROJECT_VERSION` поднят до 3, версия 2 доливается дефолтами в `normalizeProjectEditor`. Слайдеры курсора получили `*Commit`-пропсы и работают по тому же паттерну `updateState` + `commitState`, что тени и паддинг, так что перетаскивание — один шаг отмены. Границы слайдеров вынесены в `MIN_CURSOR_SIZE` / `MAX_CURSOR_SIZE` / `MAX_CURSOR_CLICK_BOUNCE` и теперь общие для UI и нормализатора.

Побочный результат: три места в `VideoEditor.tsx`, вручную перечислявшие поля проекта, свелись к одному мемо `projectEditorState` (`{...editorState}` плюс экспортные настройки). Раньше добавление поля требовало правки в трёх списках и трёх массивах зависимостей.

**5. Права на запись файлов.** Разобрано в [рисках](#риски-и-безопасность): `write-export-to-path` рассчитан на доверенный рендерер.

**6. Нет single-instance lock.** ⚠️ ЧАСТИЧНО (2026-09-12) `requestSingleInstanceLock` не встречается в `electron/` нигде. Два запущенных инстанса — конфликт за порт и неопределённость, к какому подключился агент. **Сделано:** lock взят, второй запуск отдаёт фокус первому окну. Только в упакованных сборках: `npm run dev` и Playwright-сьют запускают `dist-electron/main.js` неупакованным, причём e2e гоняет спеки параллельно — безусловный lock сломал бы тесты. **Осталось:** discovery-файл (`userData/mcp.json` с реальным портом и токеном) и порт `0` с автовыбором; он нужен в любом случае — хардкодить порт в `.mcp.json` пользователя плохо.

### Средние: учесть в дизайне тулов

**7. ID регионов последовательные, не UUID.** `zoom-${nextZoomIdRef.current++}`, при загрузке проекта счётчики восстанавливаются через `deriveNextId` (`VideoEditor.tsx:438–450`). Агент **не должен присылать id** — их выдаёт слой команд и возвращает в ответе тула. Иначе коллизии внутри сессии.

**8. Транскрипция — минуты, и только в рендерере.** Whisper-tiny крутится в воркере ([`transcribe.worker.ts`](../../src/lib/captioning/transcribe.worker.ts)); модель локальная (`env.allowRemoteModels = false`, `localModelPath` из бандла) — офлайн-обещание держится. Но `get_transcript` на десятиминутной записи — не синхронный вызов: только **Tasks**, с прогрессом. И в headless он тоже требует offscreen-окна.

**9. `imageContent` аннотации — data URL внутри JSON проекта.** Агент, добавляющий картинку, прогонит base64 через MCP-канал и раздует проект. Тул должен принимать **путь к файлу**, кодировать на нашей стороне, с лимитом размера.

**10. Новые зависимости main-процесса.** ✅ РЕШЕНО (2026-09-12): **берём официальный SDK**.

Первоначальная прикидка «stateless → можно руками на `node:http`, ноль зависимостей» оказалась неверной: stateless убрал хендшейк и сессии, но сам биндинг Streamable HTTP требует Origin-валидации, заголовков `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` со сверкой против тела запроса, base64-sentinel-кодирования (`=?base64?…?=`) для значений, не представимых в ASCII, ошибки `-32020 HeaderMismatch`, `405` на GET/DELETE, `UnsupportedProtocolVersionError` со списком поддерживаемых версий и детекции клиентов старой эры с откатом на `initialize`. Это не «немного JSON-RPC», а движущаяся поверхность, где тихая несовместимость означает «Claude Code просто не подключается».

Цена — `@modelcontextprotocol/sdk` тянет 17 зависимостей (express, hono, jose, ajv, cors, eventsource и прочее). Для приложения, которое уже возит `@xenova/transformers`, ONNX-runtime и PixiJS, размер бандла — не связывающее ограничение, а корректность против спеки — связывающее.

**Риск, который надо снять первым:** `vite-plugin-electron` должен суметь собрать это в `main.js`, а express/hono известны динамическими require, ломающими бандлеры. Проверять до того, как писать тулы поверх; при провале — externalize через `dependencies` + asar, и только если и это не выйдет, возвращаться к ручной реализации.

**11. i18n.** Панель настроек MCP (тумблер режима доверия, токен, кнопка «скопировать команду подключения») — это новые user-facing строки, а значит **13 локалей** и `npm run i18n:check`. `tsconfig.json` уже включает `electron`, так что `electron/mcp/` типизируется без правок конфигов.

### Подтвердилось — можно опираться

- **Единый source-time домен** для зумов, аннотаций, тримов, спид-регионов, транскрипта и телеметрии. Разобрано выше; это снимает целый класс ошибок.
- **Whisper полностью офлайн** — модель в бандле, удалённые модели запрещены явно.
- **`save-project-file` безопасен по умолчанию** — без диалога пишет только в текущий проект.
- **Формат проекта нормализуется при загрузке** — `projectPersistence` клэмпит и чинит каждое поле, это готовая вторая линия защиты от мусора, присланного агентом.
- **Валидаторы уже есть** — `clampPlaybackSpeed`, `clampFocusToDepth`, `getZoomScale`, границы blur-интенсивности. Слой команд их переиспользует, а не пишет заново.

### Не покрыто этим документом

- **Мультиклиповая модель.** Проект одноклиповый (об этом же предупреждает п.4 в [UPGRADES.md](../UPGRADES.md)). Агентские сценарии вида «склей три записи» невозможны, и MCP этого не меняет.
- **Linux.** Телеметрия курсора там недоступна (браузерный пайплайн), значит `get_cursor_events` и `suggest_zooms_semantic` деградируют до «только транскрипт» — ровно та слабость, за которую мы критикуем облачные клипперы. Нужен честный `capabilities`-ответ, а не пустой массив.
- **Blur-регионы за флагом.** `suggest_blur_regions` бессмысленен, пока `BLUR_REGIONS_ENABLED = false`: агент запишет регионы, а UI их не покажет. Группа 3 в этой части зависит от п.7 роадмапа.
